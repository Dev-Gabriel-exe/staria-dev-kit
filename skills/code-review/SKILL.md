# Revisão de código e entrega

1. Read requirements, diff, tests and runtime impact before reviewing style.
2. Prioritize correctness, security, data loss, permissions and reliability.
3. Cite exact files/lines for concrete findings with reproduction or failing scenario.
4. Identify missing tests and migration/deploy risks; do not speculate as fact.
5. If code changes were made, run available tests and state evidence before declaring done.
6. Separate confirmed blockers, improvements and optional refactoring.
